# 01 · 铁律一：先查记忆

> **在处理任何长任务或涉及历史代码修改时，必须先调用 `search_memory` 检索相关上下文。**
> 没有检索结果，不等于没有历史；只等于你还没查。

## 检索范围

只检索**当前项目**的记忆库：`<项目根>/memory.db`。
项目根由 `LongRunAgent(root=...)` 或 `MCPMemoryBackend(project_path=...)` 指定。
不要拿 A 项目的历史去解释 B 项目的代码 —— 先切换项目，再重新检索。

## 触发时机

以下任一情况，必须先检索：

- 开始一个新任务之前
- 修改历史代码、重构、迁移之前
- 用户说「上次」「之前」「继续」「按老方案」时
- 准备推翻现有实现之前（先确认当初为什么这么写）
- 遇到似曾相识的报错

## 检索策略

1. **提取关键词**：从任务描述里取 2–4 个实义词，中英文都保留
   （如「实现报价平台适配器」→ `报价`、`适配器`）
2. **批量检索**：每个关键词调用一次 `search_memory`，合并结果并按 id 去重
3. **先看摘要**：摘要用于判断相关性，不包含正文
4. **按需取原文**：只对最相关的 1–2 条调用 `read_raw_data`
   —— 冷热分离的意义就是不要把所有正文一股脑塞进上下文
5. **看关系**：用 `link_memory` 建的关系（`related_to` / `supersedes`）顺藤摸瓜

## 检索结果怎么用

| 情况 | 动作 |
|------|------|
| 命中同任务断点 | 走 `interrupted-task-recovery` SOP，不要新开任务 |
| 命中设计决策 | 在方案里显式引用，并说明沿用还是推翻 |
| 命中失败教训 | 先验证前提是否变化，再决定是否复用 |
| 无命中 | 如实说「未检索到相关记忆」，然后正常开始 |

## 失败处理

- 默认 `strict_memory=True`：记忆后端不可用 → **直接失败**，不允许假装查过
- 首次搭建记忆库时，可显式 `strict_memory=False`，但必须在输出里注明「本次未完成记忆检索」
- 绝不允许把「后端报错」静默当成「没有记录」

## 反模式

- ❌ 只搜任务标题，不搜核心实体
- ❌ 搜到摘要就直接下结论，从不读原文
- ❌ 把检索到的所有原文全量加载，挤爆上下文
- ❌ 记忆服务报错，继续按「无历史」推进
