# 00 · 长任务入口

> 作用：判断当前请求是否进入「长任务模式」。
> 未进入长任务模式时，不要滥用 `LongRunAgent`；简单问答直接回答。

## 判定条件

满足任意一条，即进入长任务模式：

- 用户明示「长任务 / 务必完成 / 分阶段 / 继续上次 / 断点续传」
- 预计需要多轮工具调用，或单轮可能撞到 token 上限
- 需要修改 2 个及以上历史文件
- 涉及「调研 → 设计 → 实施 → 验证」完整链路
- 需要跨会话、跨机器接着做

## 进入后必须做的四件事

1. **确认项目根**：`LongRunAgent(root=项目根)`，状态与记忆都绑定它
2. **先检索**：调用 `search_memory`，或 `LongRunAgent.start_task()`（内部已强制先检索）
3. **建状态**：任务进入 `in_progress`，读写门禁默认 `read_only`
4. **再动手**：任何写操作前确认门禁已通过 `enable_writes(原因)` 解锁

项目根决定两处数据：

```text
<项目根>/.longrun/state.json     热状态
<项目根>/memory.db              冷记忆索引
<项目根>/raw_data/<id>/raw.txt  冷记忆原文
```

## 禁止

- 没确认项目根就开始长任务
- 没检索记忆就宣称「没有历史方案」
- 没建状态就开始多阶段改造
- 用聊天里的自然语言断点，代替 `save_memory` 落盘
